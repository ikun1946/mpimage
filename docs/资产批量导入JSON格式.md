# 资产批量导入 JSON 格式说明

> 依据代码：`web/src/batch/batch.js`（导入解析）、`web/src/lib/asset-groups.js`（分组）、
> `server/src/app/products/projects/project-store.ts`（持久化）、`web/src/lib/style-transfer.js`（风格库导入）。
> 本文只描述**资产导入**；风格库导入是另一套格式，见文末。

---

## 1. 一句话结论

导入文件的顶层必须是对象，且至少包含 `role`、`scene`、`prop` 三个键中的一个：

```json
{
  "role":   { "资产名": "该资产的描述文本" },
  "scene":  { "资产名": "该资产的描述文本" },
  "prop":   { "资产名": "该资产的描述文本" }
}
```

- **键 = 资产名**（原样作为名称、分组依据、文件名）。
- **值 = 字符串**时按类型规则拆成字段；**值 = 对象**时对象的每个键值对直接成为一个字段。
- 顶层其它键（例如 `styles`、`version`、`defaultStyle`）**会被忽略**，不会导入风格。

导入成功后**每次都新建一个项目**，项目名取文件名去掉 `.json`，不会覆盖已有项目。

---

## 2. 基础约束与报错

| 约束 | 规则 | 失败表现 |
|---|---|---|
| 扩展名 / MIME | 文件名以 `.json` 结尾，或 MIME 为 `application/json` | 提示「请选择 .json 资产文件」 |
| 文件大小 | ≤ 8 MB | 提示「JSON 文件超过 8 MB，无法导入」 |
| 顶层类型 | 必须是对象；不能是数组、字符串、`null` | 「顶层必须是包含 role、scene、prop 的对象」 |
| 有效资产 | 三类合计至少 1 条 | 「没有找到 role、scene 或 prop 资产」 |
| JSON 语法 | 标准 JSON（不支持注释、尾逗号） | 「导入失败：<JSON.parse 的错误信息>」 |

补充：

- `role` / `scene` / `prop` 的值必须是对象（数组也算对象）；是字符串、数字、`null` 时该类型被**静默跳过**。
- 某类型是空对象 `{}` 不报错，只是没有资产。
- 文件里没有的类型不会出现在页签统计里；导入后自动切到第一个有资产的页签。

## 3. 推荐的三种写法

### 3.1 对象映射（最推荐）

```json
{
  "role": {
    "沈砚-少年": "【姓名】: 沈砚\n【年龄】: 17\n【状态】: 少年\n【外貌】: 清瘦，眉骨略高\n【服装】: 月白直裾"
  }
}
```

- 对象键就是资产名，解析最干净。
- 值是字符串，按第 4 节的规则拆字段。
- 同名键在 JSON 中不合法（后一个会覆盖前一个），状态请写进键名或 `【状态】`。
- 纯数字样式的键（如 `"1"`）会被 JS 提前排序，资产顺序可能与你书写的不一致；需要严格顺序时用数组写法。

### 3.2 数组 + 对象元素

```json
{
  "role": [
    { "name": "沈砚-少年", "姓名": "沈砚", "年龄": "17", "状态": "少年" }
  ]
}
```

- 名称优先级：`name` → `名称` → `角色N` / `场景N` / `道具N`（N 从 1 开始）。
- **整个对象都会变成字段**，包括 `name` 本身。因此提示词里会多出一行 `name：沈砚-少年`。
- 对象的嵌套值（数组 / 对象）会被 `JSON.stringify(value, null, 2)` 转成多行文本塞进字段值；数字、布尔会变成 `"27"`、`"true"`；空字符串会原样保留为空值字段。
- 元素写成空对象 `{}` 时，该资产字段数为 0（对象写法不会触发「名称 + 原始描述」兜底），提示词只剩标题、名称与画面要求。
- 适合「程序生成、字段名本身就是中文标签」的场景；否则不如 3.1。

### 3.3 数组 + 字符串元素

```json
{ "prop": ["青铜鹤灯；道具类别：灯具；外形：鹤颈曲伸"] }
```

- 字符串没有 `name` 属性，资产名只能退化成 `道具1`、`道具2`……
- **不推荐**，除非你不在意名称。

> 同一文件里三种写法可以混用：`role` 用对象映射、`prop` 用数组都合法。

## 4. 字段解析规则

### 4.1 角色（`role`）：`【字段】：内容`

```text
【姓名】: 沈砚
【年龄】: 27
【状态】: 战损
【外貌】: 左眉一道旧疤，肤色偏冷
```

解析正则（等价语义）：

```text
【<字段名>】<可选空白><全角或半角冒号><内容>
```

- 字段名**不能包含** `】` 或换行。
- 内容一直读到下一个 `【字段】` 之前或文本结尾，**可以跨多行**。
- 冒号全角 `：`、半角 `:` 都接受。
- 内容为空的字段被丢弃。
- 字段顺序即出现顺序，原样保留。
- 推荐每个字段单独一行；内容里的普通换行会保留。
- **分号不是角色的字段分隔符**：`【姓名】：沈砚；【外形】：清瘦` 里，`；` 会被并入「姓名」的值，变成 `沈砚；`。字段之间要靠下一个 `【` 或换行来分隔。
- 第一个 `【` 之前的文字会被忽略；正文里不要出现形如 `【xx】:` 的片段，否则会被当成新字段。

**没有匹配到任何 `【…】` 时兜底：**

```json
[
  { "label": "姓名", "value": "<资产名>" },
  { "label": "原始描述", "value": "<整段文本>" }
]
```

（文本为空时只有第一条。）

### 4.2 场景 / 道具（`scene` / `prop`）：分号分隔

```text
皇宫主殿；室内；空间定位：皇权核心；空间结构：九开间重檐；光源：高窗侧光
```

按全角 `；` 或半角 `;` 切分，逐段处理：

| 段的情况 | 结果字段 |
|---|---|
| 含有冒号且冒号前非空 | `{ 冒号前的文字: 冒号后的文字 }`（空值丢弃） |
| 第一个非空片段不含冒号 | `{ 场景名称 / 道具名称: 该段 }` |
| 非第一个非空片段，不含冒号，且整段正好是 `室内` / `室外` / `半室内` / `半室外` | `{ 环境: 该段 }` |
| 其它不含冒号的段 | `{ 补充信息: 该段 }` |

要点：

- 分号切分后会先过滤空片段，所以「第 0 段」指**第一个非空片段**；前导分号不会占位。
- 冒号必须**不在第 0 个字符**；以冒号开头的段不会成为「标签: 值」。
- 第一个非空片段永远先当名称，哪怕它正好是 `室内` / `室外`——它不会变成「环境」。
- 多个无标签段会产生多条 `补充信息`（允许重复）。
- 第一段若写成 `场景名称：xxx` 也合法，效果相同。
- 没解析出任何字段时，兜底同样是「名称 + 原始描述」。

## 5. 字段命名会影响什么

字段名不是强制的，但下面这些标签会被程序识别：

### 5.1 进入提示词的字段

生图提示词由客户端自动拼成：

```text
<角色资产|场景资产|道具资产>设定图。
资产名称：<资产名>
<字段1>：<值1>
<字段2>：<值2>
……（字段累计接近 3600 字符时，从会超出的那一行起停止追加）
画面要求：……
```

> 3600 是对「标题 + 字段行」的软上限，计算时没有计入换行符；末尾的「画面要求」始终追加，因此最终提示词可能略超 3600 字符。

- **除 `声线类型` 外，所有字段都会进入提示词**。`声线类型` 只展示、不参与生图。
- 角色若存在字段名为 **`群像`**，提示词会切换成「多人全身群像」；注意判定只看**字段名是否存在**，`【群像】: 否` 也会触发群像。不是群像就不要写这个字段。
- 建议把纯幕后信息（声优、编号、内部备注）命名为 `声线类型`，或不要写进 JSON。

### 5.2 表格里不作为字段标签展示的名称字段

- 角色：`姓名`、`群像`、`角色名称`
- 场景：`场景名称`
- 道具：`道具名称`

（详情弹窗仍会显示这些字段，只是行内标签不重复展示。）

注意：字符串资产**一个字段都没解析出来**时，兜底字段的标签就是 `姓名` / `场景名称` / `道具名称`，这条兜底会以 `姓名：<资产名>` 的形式进入提示词。所以它并非纯展示字段。

### 5.3 行摘要列取哪个字段

按顺序取第一个**存在**的字段（只看字段在不在，不看值是否为空）：

| 类型 | 摘要字段优先级 |
|---|---|
| 角色 | `颜值定位` → `人设描述` → 第 2 个字段 → 第 1 个字段 |
| 场景 | `空间定位` → `空间结构` → `光源` → 第 2 个字段 → 第 1 个字段 |
| 道具 | `道具类别` → `美学定位` → `外形` → 第 2 个字段 → 第 1 个字段 |

取到的值截断到 62 字显示。若命中的字段值为空字符串，摘要会直接回退到该资产的原始文本（`raw`），不会再试下一个字段。

### 5.4 分组（同角色多状态 / 同场景多区域）

角色与场景会按「主体名」归组；道具不分组。

**名称后缀规则**（两种都生效）：

1. 末尾括号：`沈砚（少年）`、`皇宫(外景)`、`沈砚【战损】`、`皇宫[偏殿]`
   → 括号前为主体，括号内为状态/区域。
2. 分隔符：`-`、`－`、`—`、`–`、`_`、`·`、`・`、`/`、`|`、`｜`
   → 第一个分隔符前为主体，其余部分拼接为状态/区域。
   例：`沈砚-战损` → 主体 `沈砚`，状态 `战损`；`皇宫·偏殿` → 主体 `皇宫`，区域 `偏殿`。

**字段优先级高于名称后缀**：

| 类型 | 识别为二级标签的字段名 |
|---|---|
| 角色 | `状态`、`角色状态`、`形态`、`阶段`、`时期`、`造型`、`版本`、`变体`、`身份` |
| 场景 | `子场景`、`区域`、`分区`、`场景类型` |

即：`沈砚-战损` 里若还有 `【状态】: 重伤`，行内状态标签显示「重伤」，但**主体仍是 `沈砚`**（主体只从名称取）。

组内超过 1 条才显示父行 + 缩进子行；分页按组切分，同一主体不会拆到两页。

## 6. 导入时的默认值

| 项 | 角色 | 场景 | 道具 |
|---|---|---|---|
| 默认画幅 | `3:4` | `16:9` | `1:1` |
| 名称兜底 | `角色N` | `场景N` | `道具N` |
| 资产 id | `role-1`、`role-2`… | `scene-1`… | `prop-1`… |

- 画幅可在界面逐项修改；可选值来自后端 `/api/config`，内置兜底为 `1:1`、`4:3`、`3:4`、`16:9`、`9:16`。
- 初始风格取当前项目的默认风格；状态为「未生成」，结果为空。
- 每条资产的提示词在导入时即生成，之后可在详情弹窗里改，改了不会被重新拼装覆盖。

## 8. 常见错误与规避

| 现象 | 原因 | 修正 |
|---|---|---|
| 导入报「没有找到 role、scene 或 prop 资产」 | 顶层是数组；或三个键都不是对象 | 改成 `{ "role": {...} }` 结构 |
| 角色字段只显示「姓名 + 原始描述」 | 用了半角括号 `[姓名]`、中文方括号外的符号，或冒号写成 `=` | 统一用 `【姓名】：内容` |
| 角色只拆出一个字段 | 内容里出现 `【` 被当成下一个字段开头 | 正文避免使用 `【】`，或改写字段名 |
| 角色最后一个字段末尾多出分号 | 角色不按分号分段，`；` 并进了上一个值 | 字段之间换行，不要用分号 |
| 场景字段名带方括号 | 场景/道具不走 `【】` 解析，`【场景名称】` 会原样成为字段名 | 场景/道具用 `场景名称：xxx` |
| 场景只剩一段 | 用了顿号 `、` 或逗号分隔 | 只用 `;` / `；` 分隔 |
| 想让 JSON 指定画幅 / 风格却没生效 | 导入固定使用类型默认画幅与项目默认风格；`ratio`、`styleId`、`prompt` 只会被当成普通字段 | 导入后在界面逐项调整 |
| 场景第一段变成了「补充信息」 | 文件以分号或冒号开头，第一段不是名称 | 让第一段就是场景名，或写 `场景名称：xxx` |
| 提示词出现多余内容 | 对象写法里 `name`、`id` 等键也被当成字段 | 改用字符串值写法，或删掉无关键 |
| 角色被误判成群像 | 写了 `【群像】` 字段（哪怕值是「否」） | 非群像不写该字段 |
| 同名资产互相覆盖 | JSON 对象键重复 | 键名加上状态/区域后缀 |
| 资产名带路径后被清洗 | 文件写入磁盘时会替换 `<>:"/\|?*` 等字符 | 名称避免 Windows 保留字符 |

## 9. 导入后数据去了哪里（开发者参考）

1. 前端 `importFile()` 解析文件 → `normalizeAssets()` 生成资产数组。
2. `POST /api/projects` 新建项目（只传 `name`、`fileName`）。
3. `PATCH /api/projects/:id` 把 `assets`、`styles`、`defaultStyle`、`bulkParams` 写回。
4. 服务端 `ProjectStore` 落盘到 `projects.json`（默认项目根目录，可用 `PROJECT_DATABASE_PATH` 改路径）。
   - 项目顶层按白名单重建，只保留 `id / ownerId / name / fileName / importedAt / updatedAt / assets / styles / defaultStyle / bulkParams`；多余顶层键会被丢弃。
   - `assets` 只校验「是不是数组」，数组内的资产对象原样保存，不做逐字段校验。
   - `styles` 会被逐条重建（缺 `id` 的条目丢弃）；`defaultStyle` 会校正为确实存在的风格 id。
5. 浏览器 `localStorage` 另存一份快照（键 `moying.assetStudio.v2.<userId>`），所以同一浏览器有本地副本，后端 `projects.json` 是跨设备共享的那一份。

落盘后的单条资产形状（导入值之外还会带上运行时状态）：

```json
{
  "id": "role-1",
  "type": "role",
  "name": "沈砚-少年",
  "fields": [{ "label": "姓名", "value": "沈砚" }],
  "raw": "【姓名】: 沈砚……",
  "ratio": "3:4",
  "styleId": "",
  "status": "idle",
  "prompt": "角色资产设定图。\n资产名称：沈砚-少年\n……",
  "resultUrl": "",
  "width": 0,
  "height": 0,
  "error": "",
  "updatedAt": "",
  "referencePath": "",
  "history": [],
  "primaryUrl": ""
}
```

`referencePath`、`history`、`primaryUrl` 是生成后的运行时字段，导入文件里写了也不会被资产导入流程读取（`normalizeAssets` 不读取它们）。

## 10. 附：风格库 JSON（另一套格式）

风格库的「导入 JSON」按钮读的是**风格数据**，不是资产数据，两者不能混用。

导出格式：

```json
{
  "format": "huajing-styles",
  "version": 1,
  "exportedAt": "2026-11-06T08:00:00.000Z",
  "styles": {
    "role":  [{ "id": "style-role-1", "name": "工笔重彩·角色", "description": "……", "updatedAt": "" }],
    "scene": [{ "id": "style-scene-1", "name": "电影写实·场景", "description": "……", "updatedAt": "" }],
    "prop":  [{ "id": "style-prop-1", "name": "器物考据·道具", "description": "……", "updatedAt": "" }]
  },
  "defaultStyle": { "role": "style-role-1", "scene": "style-scene-1", "prop": "style-prop-1" }
}
```

导入规则：

- 也接受裸的 `{ "role": [...], "scene": [...], "prop": [...] }`（没有 `styles` 包装时，直接读顶层三个键）。
- 每种类型必须是数组；每个风格必须有非空 `name`，否则丢弃。
- `name` 超 40 字截断，`description` 超 3000 字截断。
- 合并按名称（去首尾空格、忽略大小写）：同名**覆盖描述并保留本地 id**，新名称追加；**不删除**任何现有风格。
- 文件中的 `defaultStyle` 按名称对应到合并后的本地风格，能对上就设为默认。
- 文件上限 2 MB。

两个容易踩的边界：

- 如果写了 `styles` 键但它是空对象 `{}`，会**屏蔽**顶层的 `role` / `scene` / `prop`，最终报「文件里没有可导入的风格」。
- 资产 JSON 的**数组写法**（元素是带 `name` 的对象）喂给风格导入不会报错，会被当成风格合并进去，产生一批描述为空的脏风格。两套 JSON 请勿混用。

## 11. 最小可用模板

```json
{
  "role": {
    "角色名-状态": "【姓名】: 角色名\n【状态】: 状态\n【外貌】: ……\n【服装】: ……"
  },
  "scene": {
    "场景名-区域": "场景名；室内；空间结构：……；光源：……；氛围：……"
  },
  "prop": {
    "道具名": "道具名；道具类别：……；外形：……；材质：……"
  }
}
```

把它保存为 UTF-8 的 `.json` 文件，拖进「资产导入」页或点「导入资产 JSON」即可。
